# Report Preprocessing Pipeline

Condenses long vendor threat reports into one-paragraph entity-preserving outputs that are used downstream by (a) the CSKG-Guided RAG baseline for entity extraction and (b) embedding-based retrieval. The shipped output lives at `corpus_reports/preprocessed_reports.jsonl`; each row carries a `preprocessed` field holding the condensed text.

## Design contract: entity-preserving condensation

Downstream consumers (`baselines/ctinexus_lite/pipeline.py` and the `t2p` multi-doc-synthesis prompt renderer) **never see the raw report again** — only the `preprocessed` field. That field is therefore not free-form output; it is the contract surface for downstream retrieval.

The prompt (see `_build_preprocessing_prompt` in `main.py`) enforces a hard invariant: **every CTI entity mention in the source must survive verbatim into the preprocessed text.** The STIX-aligned entity types that must be preserved mirror `baselines/ctinexus_lite/ontology.py:ENTITY_TYPES`:

| Type | What to keep verbatim |
|---|---|
| `threat_actor`  | Group / operator names AND all aliases (e.g., APT29 / Cozy Bear / Nobelium / Midnight Blizzard) |
| `campaign`      | Named operations (Operation Aurora, EleKtra-Leak) |
| `malware`       | Family / instance names AND variant suffixes (LockBit 3.0, Cobalt Strike Beacon) |
| `tool`          | Dual-use tools (PsExec, Mimikatz, AnyDesk) |
| `attack_pattern`| ATT&CK technique IDs incl. sub-techniques (T1059.001, T1566.001) and names |
| `vulnerability` | Every CVE ID (CVE-2024-3400) with affected product/version |
| `weakness`      | Every CWE / CAPEC ID (CWE-79, CAPEC-66) |
| `indicator`     | IoCs: IPs, domains, URLs, hashes, paths, registry keys, emails |
| `identity`      | Named victim organisations and sectors (no generalisation to "European firms") |

What MAY be cut: vendor self-promotion, generic background, redundant repetition, legal boilerplate, reference link blocks at the end of the post.

This contract is the reason a CSKG built over `preprocessed_reports.jsonl` can match the recall of a CSKG built over the full corpus despite a >10× compression ratio: the LLM removes prose noise, not CTI signal.

> **Note on the shipped artifact.** The `corpus_reports/preprocessed_reports.jsonl` currently in this repo was generated by an earlier, less strict prompt. To benefit from the entity-preservation contract above, re-run the pipeline (input file: the original blog corpus, not redistributed for copyright reasons).

## I/O

- **Input:** `corpus_reports/blog_raw.jsonl` (or any JSONL with `id`, `title`, `publish_date`, `link`, `clean_text`, `metadata`). The raw vendor reports are not redistributed for copyright reasons; supply your own corpus matching this schema.
- **Output:** `corpus_reports/preprocessed_reports.jsonl` (each row gains a `preprocessed` field). This is the shipped retrieval corpus consumed by `baselines/ctinexus_lite/pipeline.py` and the t2p multi-doc-synthesis renderer.
- **Model:** `gpt-4o` (default; override by editing `LLM_MODEL` at the top of `main.py`).
- Edit `INPUT_FILE` / `OUTPUT_FILE` at the top of `main.py` to point at a different corpus.

## setup
1. Install dependencies:
```bash
pip install -r requirements.txt
```

2. Set up your OpenAI API key:
```bash
cp env.example .env
# Edit .env and add your OpenAI API key
# The .env file should be in this directory
```

## usage
```bash
# Process all blog entries
python main.py

# Test mode (process only first 3 entries)
python main.py --test
```
